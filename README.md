# Grok Telegram Bot

Telegram-бот с интеграцией xAI API — текстовый диалог, анализ изображений, генерация картинок и видео.

## Запуск

### Docker (рекомендуемый)

```bash
cp .env.example .env
# заполнить BOT_TOKEN, XAI_API_KEY, DB_PASSWORD
docker compose up --build -d
```

Бот сам применит миграции и запустится в polling-режиме.

### Локально

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# поднять PostgreSQL, прописать DATABASE_URL в .env
alembic upgrade head
python -m bot.main
```

## Команды бота

| Команда | Описание |
|---|---|
| `/start` | Регистрация и приветствие |
| `/model` | Выбор модели через inline-клавиатуру |
| `/new` / `/reset` | Сброс контекста диалога |
| `/status` | Текущая модель и количество сообщений в сессии |
| `/imagine <prompt>` | Генерация изображения (grok-imagine-image) |
| `/imagine pro <prompt>` | Генерация в pro-качестве (grok-imagine-image-pro) |
| `/video <prompt>` | Генерация видео (grok-imagine-video) |

Текстовые сообщения обрабатываются как диалог. Фотографии анализируются через vision.

## Архитектурные решения

**PostgreSQL вместо SQLite/Redis.** Бот хранит историю сообщений, пользователей и данные rate limiting. PostgreSQL выбран потому что он нужен в продакшене в любом случае — SQLite не выдерживает конкурентную запись от нескольких пользователей, а Redis не подходит для персистентной истории диалогов. Плюс pgvector уже в образе на случай будущего RAG.

**Мягкий сброс контекста.** При `/reset` не удаляются сообщения — ставится `cleared_at` timestamp на пользователе. История загружается только после этой метки. Это дешевле DELETE и позволяет при необходимости восстановить старый контекст.

**Streaming через edit_text.** Ответ модели стримится чанками, сообщение обновляется каждые ~30 символов с throttle 0.3с. Это баланс между отзывчивостью и лимитами Telegram API на редактирование. Курсор `▌` показывает что генерация идёт.

**Модерация отдельным запросом.** Перед отправкой в основную модель пользовательский ввод проходит через `grok-3-mini` с промптом-классификатором. Дешёвая модель отсекает запрещённый контент до того, как он попадёт в дорогую. Если модерация сама упала — запрос пропускается, чтобы не блокировать пользователя.

**Видео через фоновый поллинг.** xAI отдаёт видео асинхронно — submit возвращает request_id, дальше нужно поллить статус. Вынесено в `asyncio.create_task` чтобы не блокировать event loop. Пользователь видит таймер ожидания.

**Единый OpenAI-клиент.** xAI API совместим с OpenAI SDK — используется `AsyncOpenAI` как синглтон. Один клиент на весь бот, без лишних абстракций.

## Что бы сделал иначе при наличии времени

- **Webhook вместо polling** — для продакшена с nginx/caddy перед ботом
- **Middleware для модерации** — сейчас проверка вызывается в каждом хендлере, лучше вынести в aiogram middleware
- **Retry-логика** — при 429/5xx от xAI API автоматический retry с exponential backoff
- **Очередь для видео** — сейчас каждый запрос на видео это отдельный background task, при нагрузке лучше через очередь (arq/celery)
- **Админка** — базовая статистика по пользователям и запросам

## AI-инструменты

При разработке использовался Claude Code (CLI) для ускорения рутинных задач:

- **Генерация бойлерплейта** — начальная структура проекта, модели SQLAlchemy, миграции Alembic. Схему БД и выбор полей определял сам, Claude писал ORM-код по описанию.
- **Хендлеры** — логику стриминга и обработки ошибок писал с подсказками Claude, но паттерн edit_text с throttle и cursor подбирал вручную, потому что первые варианты упирались в rate limit Telegram.
- **Тесты** — сгенерированы через Claude, потом правил руками — начальные варианты мокали слишком много и не ловили реальных багов.
- **Docker/CI** — Dockerfile и docker-compose написаны с нуля с помощью Claude, entrypoint с alembic upgrade head — моё решение.
- **Модерация** — промпт для классификатора и выбор grok-3-mini как дешёвой модели — мои, реализацию сервиса дописывал Claude.

В целом Claude использовался как ускоритель: архитектурные решения, выбор подходов и отладка — мои, написание кода по готовой спецификации — частично делегировал.
